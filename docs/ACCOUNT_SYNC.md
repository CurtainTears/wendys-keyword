# 换设备，继续使用同一份词库

在两台设备上打开**同一个服务地址**，用相同邮箱和密码登录。私人词库、回收站与练习记录归属于账号，不依赖原设备的浏览器缓存。

新用户先向管理员领取一次性邀请码，在“使用邀请码注册”中创建账号；默认 7 天有效。已有账号与同账号换设备登录不需要邀请码。管理员在管理页直接发放，首次初始化方式见 [README](../README.md#管理员发放邀请码)。

`http://127.0.0.1:3000` 只供当前电脑使用。手机和其他电脑需要访问统一的 HTTPS 服务地址；部署方法和持久化磁盘要求见 [README](../README.md#在手机与电脑之间使用)。不能在每台设备各运行一份独立数据库来获得同步。

## 登录后会同步什么

- **私人词库**：新建、导入、复制、编辑、移入回收站和恢复。
- **学习状态**：词内断点、词库遍数和已练队列、动态错词本及手动移出／恢复；详见 [学习状态](LEARNING.md)。
- **练习记录**：每轮的词库版本、词条与释义、完成时间和统计；页面展示最近 100 轮，导出包含全部记录。
- 词库及正在查看的记录页每 20 秒检查更新；重新聚焦、恢复可见或恢复联网也会检查。需要立即确认时，点击右上角同步状态。

音效、主题等设备偏好留在当前浏览器。旧版访客词库和记录仍保留在本机；登录后可复制旧词库，不自动认领访客记录或旧昵称成绩。未登录不能访问工作台，退出后旧视图立即清空并锁定。

## 断网和编辑冲突如何处理

已载入的一轮练习可以在断网后完成。记录先保存在浏览器的原账号队列，再提交服务；重新打开页面、恢复网络或重新登录原账号后会补传。每轮的独立标识避免重复保存，补传保留完成时间。

词库编辑需要连接服务。保存失败时草稿留在编辑器，可重试或导出。如果另一台设备已经保存了新版，当前保存会提示冲突，不覆盖新版；先导出需要保留的草稿，再明确载入最新版本。

本机存储也失败时，每轮结果保留在当前页面内存中，可重试或导出；此时不要强制关闭页面或清理浏览器数据。尚未上传的记录不可能在另一台设备读取，必须先完成原设备的补传。

## 切换账号不会接管上一人的数据

- 服务端始终根据登录会话检查所有权，前端传入的账号 ID 不能指定数据归属。
- 前端请求附带预期账号；注销和修改密码也会检查，旧标签页不能操作新账号。
- 同源标签页共享登录状态。退出或切换时，其他标签页会清除旧账号的词库、记录、搜索内容和草稿；旧请求返回后不会回填新账号页面。打开编辑器期间仍检查账号。
- 待同步结果绑定练习开始时的账号。账号 B 看不到、不会提交账号 A 的队列；重新登录 A 才会继续。
- 同一账号在独立设备上可同时登录。普通退出只注销当前会话，修改密码会注销其他设备，原账号的数据仍保留。

邮箱目前作为登录标识，未接入邮箱验证或邮件找回。密码至少 10 位，使用 Better Auth 管理散列、限流和 HttpOnly 会话 Cookie。公开运营前需配置邮件验证与找回服务。

## 验收方式与证据

```bash
npm test
npm run build
```

账号与同步回归检查位于 `tests/accounts.test.mjs`、`tests/sync.test.mjs` 和 `tests/integration.test.mjs`，覆盖独立 Cookie 会话、账户归属、并发版本、过期与续期、持久化重启、离线补传、异步响应丢弃和异常响应。`tests/invites.test.mjs` 覆盖邀请码前置拒绝、并发一次性使用、失败回滚、过期与撤销、管理命令和备份；注册与私人词库并发写入不会相互影响。

2026-10-25 浏览器验收使用独立测试数据库，以及 `127.0.0.1` / `localhost` 两套相互隔离的 Cookie 与浏览器存储，模拟两台设备；另开同源标签页检查账号切换。未使用个人账号或修改日常数据库中的私人数据。

实际完成了注册、独立设备登录、新建和跨设备编辑、旧稿冲突提示、真实按键输入、断网完成一轮、重开页面补传、记录页自动更新、切换账号和旧标签页清空。账号 A 的 2 轮记录与账号 B 的 1 轮记录分别可见，没有混入对方页面；离线补传只增加一轮，时间保持为完成时间。
